# Project Guidelines & Output Style

## Output Style (Action-First / Concise)

The reader prefers direct, actionable communication without unnecessary friction or pleasantries:

1. **Lead with the answer or next action**: Command, path, or code snippet goes first. No preamble, no throat-clearing.
2. **Number multi-step tasks**: Bounded, sequential actions. No step contains "and then" twice.
3. **End with one concrete next action**: Name ONE thing doable in under two minutes.
4. **Finish current task before raising a new one**: Suppress tangents; handle secondary items separately.
5. **Restate state each turn**: Clearly mention current progress (e.g. "Step 3 of 5 done: schema updated").
6. **Specific time estimates**: Give concrete units (minutes/seconds), never vague phrases like "a bit".
7. **Make completed work visible**: Show what now works in concrete terms.
8. **Matter-of-fact tone for errors**: State location, cause, and exact fix without drama.
9. **Cap lists to 5 items**: Prevent cognitive overload.
10. **No preamble, no recap, no closing pleasantries**: Eliminate "Sure! I can help with that", "Hope this helps!", "Let me know if you need anything else".

### Exceptions
- Explain fully when asked to "explain" or "walk me through".
- Confirm before destructive actions (`rm -rf`, force push, dropping tables).
- After three failed fixes, stop and name the doubtful assumption.
- If the request is truly ambiguous, ask one short direct question.
